## ۴) شاهد QA مرورگری زنده (Chromium واقعی، استک کامل API+Vite+PGlite)

اسکریپت: `backend/scripts/qa-cashback-browser.local.cjs` (محلی، کامیت نمی‌شود) — **۱۶/۱۶ PASS**:

| بررسی | نتیجه |
|---|---|
| ورود ادمین + رندر برج کنترل | PASS |
| هاب کش‌بک: نمای کلی (بدهی/موجودی‌ها)، قوانین (قانون ۱۰٪ QA)، کیف پول‌ها، دفترکل، تنظیمات | PASS ×۵ |
| تب کیف پول در Customer 360 | PASS |
| ورود OTP فروشگاه (۰۹۳۵۱۱۱۲۲۳۳ / کد ۱۲۳۴۵) | PASS ×۲ |
| نمای کیف پول حساب: موجودی‌ها + تاریخچه + سند «افزایش دستی» + مبلغ ۲۵۰٬۰۰۰ تومان | PASS ×۳ |
| افزودن به سبد → تسویه‌حساب → باکس کیف پول → ورود ۱۰۰٬۰۰۰ → سطر کسر و جمع جدید (۴٬۶۹۰٬۰۰۰−۱۰۰٬۰۰۰=۴٬۵۹۰٬۰۰۰) | PASS ×۴ |

شاهد E2E سطح API روی سرور زنده (python/urllib، بدون شبیه‌سازی):
- قانون ۱۰٪ → پرداخت+تحویل KV-100000 (۴۹٬۸۰۰٬۰۰۰ ریال) → موجودی قابل استفاده **۴٬۹۸۰٬۰۰۰ ریال** (آزادسازی تنبل با تأخیر ۰)
- سفارش جدید با `walletRial=3000000` → total از ۴۶٬۹۰۰٬۰۰۰ به **۴۳٬۹۰۰٬۰۰۰** و `walletRedeemedRial=3000000` در اسنپ‌شات
- بازپخش همان idempotency-key → همان سفارش، **بدون کسر دوباره** (used ثابت ۳٬۰۰۰٬۰۰۰)
- درخواست بیش از سقف → **۴۰۰** با پیام فارسی «حداکثر مبلغ قابل استفاده از کیف پول ۱۹۸۰۰۰۰ ریال است.»

## ۵) باقی‌ماندهٔ صادقانه

- P3-10 (a11y تکمیلی)، P3-11 (RTL آرایشی)، P3-12 (دادهٔ seed)، بخش کدهای روش ارسال (by design) و بازبینی واژه‌به‌واژهٔ عنوان‌ها — در جدول بالا با وضعیت واقعی ثبت شدند؛ هیچ‌کدام رفتار کاربری را نمی‌شکنند.
