# واژه‌نامه نهایی پلتفرم کلبه وینتیج (Prompt 4 — §177-§181)

| اصطلاح فارسی (Canonical UI) | اصطلاح فنی | تعریف دقیق |
|---|---|---|
| در انتظار تکمیل | payable `pending` | بدهی کلبه به تأمین‌کننده ایجاد شده ولی سفارش هنوز نهایی نشده است. |
| در دوره نگهداری تسویه | payable `held` (Settlement Hold) | مبلغ قابل پرداخت است ولی تا پایان دوره Hold (پیش‌فرض ۷۲ ساعت، قابل تنظیم) آزاد نمی‌شود. |
| آماده تسویه | payable `eligible` | دوره Hold تمام شده؛ مبلغ آماده قرارگیری در تسویه بعدی است. |
| قرارگرفته در تسویه بعدی | payable `scheduled` | مبلغ به یک سند تسویه زمان‌بندی‌شده (SET-…) متصل شده است. |
| آماده بررسی مالی | settlement `review` | سند تسویه ساخته شده و منتظر تأیید نقش مالی است (کنترل دوگانه بالای آستانه). |
| آماده واریز بانکی | settlement `approved` / awaiting transfer | تأیید شده؛ منتظر ثبت دستی واریز بانکی است. **هیچ پرداخت خودکاری وجود ندارد.** |
| تسویه‌شده | settlement `paid` | واریز بانکی با مرجع واقعی ثبت شد؛ سند تغییرناپذیر است. |
| مسدود | payable/settlement `blocked` | به دلیل اختلاف، بازگشت یا تصمیم مالی مسدود شده است. |
| مبلغ قابل بازیافت | Recovery (RCV-…) | طلب کلبه از تأمین‌کننده پس از بازگشتِ بعد از پرداخت؛ از تسویه‌های بعدی کسر (offset) می‌شود، هرگز موجودی منفی نمی‌سازد. |
| برداشت (قدیمی) | **Legacy Withdrawal** (WDR-…) | مدل قدیمی برداشت کیف‌پول. **فقط تاریخچه خواندنی.** ایجاد برداشت جدید `WITHDRAWAL_DEPRECATED` برمی‌گرداند. در هیچ سند جدیدی جز با پسوند «قدیمی» ظاهر نمی‌شود. |
| دفتر کل | General Ledger (double-entry) | منبع واقعیت مالی؛ کیف‌پول صرفاً projection است. |
| سند تسویه | Scheduled Settlement (SET-…) | جایگزین کامل Withdrawal: hold → eligible → scheduled → review → واریز دستی → paid. |
| حساب بانکی تأییدشده | Verified bank account + frozen snapshot | واریز فقط به IBAN تأییدشده با snapshot منجمد در لحظه تأیید. |
| پیش‌پرداخت (بایگانی) | Advance (archived) | مدل قدیمی پیش‌پرداخت؛ فقط خواندنی زیر «پرداخت و تسویه». |
| اعتبار پرو مجازی | Try-On credit | یک واحد = یک ساخت تصویر. دفتر append-only با `balance_after >= 0`. |
| بسته پرو مجازی | Try-On package | بسته اعتبار قابل تنظیم توسط ادمین (نام/تعداد/قیمت/انقضا) — هاردکد نیست. |
| سهمیه رایگان | Free quota | اعتبار رایگان یک‌بارهٔ هر کاربر از سیاست `tryon_policy` (site_settings). |
| خرید اعتبار | tryon_credit_purchase (TRY-…) | از خط پرداخت یکتا (payment_intents, purpose=`tryon`) عبور می‌کند؛ اعتبار دقیقاً یک‌بار پس از تأیید پرداخت (§199). |
| ظرفیت اعلامی | Declared capacity | عدد اعلامی تأمین‌کننده؛ **موجودی WMS نیست** و هرگز قابل فروش مستقیم نیست. |
| موجودی نزد کلبه | Supplier stock-at-Kolbe | موجودی فیزیکی تأمین‌کننده در انبار کلبه (supplier-owned)، فقط با اسناد WMS تغییر می‌کند. |
| تأیید و انتشار | Approve & publish | مجوز حضور محصول تأمین‌کننده در بازارچه عمده. **هیچ موجودی‌ای نمی‌سازد** (تست رگرسیون «approval never mutates stock»). |
| ارسال درخواست اصلاح / رد محصول | changes_requested / rejected | مرحله دوم «عدم تأیید» در بازبینی دومرحله‌ای؛ دلیل اجباری و snapshot در سوابق. |
| ریال/تومان | Integer RIAL backend / Toman UI | پول همیشه ریالِ صحیح در سرور؛ UI تومان = ریال ÷ ۱۰. |

## قواعد نام‌گذاری اسناد
`INV` فاکتور · `SET` تسویه · `WDR` برداشت قدیمی · `TXN` تراکنش · `RTN` بازگشت · `COOP` درخواست همکاری · `CN` اصلاحیه · `PAYB` بدهی تأمین‌کننده · `RCV` بازیافت · `TRY` خرید اعتبار پرو مجازی
